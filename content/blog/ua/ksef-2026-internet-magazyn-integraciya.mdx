KSeF стає обовʼязковим у Польщі з 2026 року, і власники інтернет-магазинів починають панікувати: чи "зламається" їхній WooCommerce, Shopify чи самописний магазин під нові правила. Я роблю інтернет-магазини та інтеграції, тож поясню KSeF з погляду розробника - і так, щоб це було зрозуміло україномовному підприємцю в Польщі. Кого це стосується, з якої дати, що реально змінюється в коді магазину і як підключити систему, щоб рахунки виходили самі, а не переписувалися бухгалтером вручну.

## Що таке KSeF і кого він стосується у 2026

KSeF (Krajowy System e-Faktur, Національна система електронних рахунків) - це центральна платформа Міністерства фінансів Польщі. Рахунки потрапляють туди як структурований XML за схемою FA(3), а не як PDF. Рахунок юридично "зʼявляється" лише після того, як KSeF його прийняв і присвоїв номер KSeF.

Терміни за законом такі:

- **1 лютого 2026** - обовʼязок для найбільших платників із продажами понад 200 млн зл за 2024 рік.
- **1 квітня 2026** - обовʼязок для всіх інших платників VAT, тобто для переважної більшості магазинів.
- Адміністративні штрафи (до 100% суми VAT за помилковим рахунком) вмикаються лише з **1 січня 2027**, тож є вікно, щоб спокійно впровадити й протестувати.

Важлива деталь: отримувати рахунки через KSeF фактично мають майже всі вже з лютого, навіть якщо виставляти самому потрібно лише з квітня. Якщо ви закуповуєте товар у постачальників за рахунком, ці вхідні рахунки все одно лежатимуть у KSeF.

## B2B, B2C і продажі за кордон - це не одне й те саме

Тут найбільше плутанини, бо KSeF охоплює не всі продажі однаково.

- **B2B (бізнесу)** - ядро KSeF. Кожен рахунок для клієнта з польським NIP іде через API як FA(3). Тут інтеграція обовʼязкова.
- **B2C (приватна особа)** - фізособа без фірми не має облікового запису в KSeF. Такі рахунки виставляються поза системою, а продаж усе одно йде через фіскальну касу. Магазин має розуміти, чи вказав покупець NIP, і спрямовувати документ правильним шляхом.
- **Продажі за кордон, OSS/IOSS** - продажі споживачам в інші країни ЄС за процедурою OSS/IOSS живуть за своїми правилами і не потрапляють у KSeF як внутрішній B2B.

Для розробника це означає одне: у логіці магазину потрібна розвилка. Поле NIP у кошику, валідація і рішення "цей рахунок іде в KSeF, а той ні". Без цього магазин або відправить у KSeF те, чого не повинен, або пропустить рахунок, який зобовʼязаний був відправити.

## Що це означає технічно для Shopify, WooCommerce і самопису

Сам магазин не "розмовляє" з KSeF однією кнопкою. Потрібен міст: шар, який бере дані замовлення, складає коректний XML FA(3), авторизується в API KSeF (токеном чи сертифікатом/печаткою), відправляє рахунок, отримує номер KSeF і зберігає його поруч із замовленням.

- **WooCommerce** - найбільше свободи. Підключаю інтеграцію через плагін або власний модуль, який слухає оплачене замовлення і запускає відправку в KSeF. Сюди можна вбудувати будь-яку логіку B2B/B2C.
- **Shopify** - тут зазвичай усе йде через застосунок, що звʼязує Shopify з польською системою виставлення рахунків чи бухгалтерією, у якої вже є офіційна інтеграція з KSeF. Shopify нічого не знає про польські рахунки, тому фактурування виноситься назовні.
- **Самописний магазин (Next.js, headless)** - пишу інтеграцію прямо до API KSeF або через сервіс-фактуровню з API. Повний контроль над тим, коли рахунок іде, як виглядає XML і що робити, якщо KSeF повернув помилку.

Найчастіше розумніше не генерувати XML "з нуля" всередині магазину, а звʼязати магазин із системою виставлення рахунків чи бухгалтерією, у якої вже є сертифікована інтеграція з KSeF, а магазин лише передає дані замовлення. Менше ризику, що зміна схеми FA(3) з боку Мінфіну покладе магазин.

## Як іде впровадження в мене і скільки коштує

Зазвичай роблю це в кілька кроків: аудит продажів (частка B2B проти B2C, чи є OSS/IOSS), вибір шляху (пряме API чи через фактуровню), підключення генерації FA(3), авторизація в KSeF, обробка відповіді й номера KSeF, плюс тести на передпродакшн-середовищі Мінфіну до того, як щось піде в бойовий режим.

Орієнтовні ціни:

- Інтеграція магазину з KSeF на базі готової фактуровні з API - від 1500-2500 €, залежно від кількості випадків (B2B, B2C, закордон, корекції).
- Самописний магазин із прямим API KSeF і власною логікою - від 4000 €.
- Сам новий інтернет-магазин під ключ - від 2500 € (Shopify/Woo), headless від 4000 €, а інтеграцію KSeF додаю модулем.

Безкоштовну фіксовану оцінку даю за 24 години. Докладніше про створення магазину - в [послузі інтернет-магазину](/ua/poslugy/internet-magazyn).

## Часті помилки, яких варто уникати

- **Вважати KSeF генератором PDF.** Це не гарна роздруківка, а структурований XML, який Мінфін валідує. Невірна структура - рахунок відхилено.
- **Немає обробки помилок API.** KSeF іноді не відповідає або повертає помилку. Якщо в магазину немає черги повторних спроб і логів, рахунки тихо "зникають" і ніхто не помічає до кінця місяця.
- **Ігнорувати дату виставлення.** Номер KSeF присвоюється в момент прийому документа, і це впливає на те, коли рахунок формально виставлено. Це треба акуратно зіставити з датою продажу.
- **Робити все по-старому вручну.** Раз уже все одно треба лізти в код, краще одразу звʼязати KSeF із бухгалтерією, щоб дані йшли автоматично, а не через вивантаження в Excel.

Якщо у вас магазин і незрозуміло, чи потрапляєте ви під обовʼязок з квітня 2026 і як технічно підключити KSeF, напишіть - розберу ваш випадок і запропоную найпростіший шлях інтеграції. Залиште заявку на [сторінці контактів](/ua/kontakt), оцінка за 24 години.

## FAQ

**З якої дати KSeF обовʼязковий для мого магазину?**
Для найбільших фірм (продажі понад 200 млн зл за 2024) з 1 лютого 2026, для всіх інших платників VAT з 1 квітня 2026. Адміністративні штрафи вмикаються лише з 1 січня 2027, тож час на впровадження й тести є. Отримувати рахунки через KSeF фактично мають майже всі вже з лютого.

**Чи стосується KSeF продажів приватним особам (B2C)?**
Не так, як B2B. Приватна особа без фірми не має облікового запису в KSeF, тому рахунки B2C виставляються поза системою, а продаж усе одно йде через фіскальну касу. Магазин має розуміти, чи вказав покупець NIP, і спрямовувати документ відповідно. Продажі OSS/IOSS в інші країни ЄС теж рахуються окремо.

**Як технічно підключити KSeF до WooCommerce чи Shopify?**
У WooCommerce через плагін або власний модуль, який слухає оплачене замовлення, складає XML FA(3) і відправляє в API KSeF. У Shopify зазвичай через застосунок, що звʼязує магазин із польською системою виставлення рахунків, у якої вже є інтеграція з KSeF. У самописному магазині пишу інтеграцію прямо до API або через сервіс-фактуровню з API.

**Скільки коштує інтеграція магазину з KSeF?**
На базі готової фактуровні з API - від 1500-2500 € залежно від кількості випадків (B2B, B2C, закордон, корекції). Самописний магазин із прямим API KSeF і своєю логікою - від 4000 €. Оцінка безкоштовно за 24 години.

**Чи треба мені самому генерувати XML FA(3)?**
Вручну робити не потрібно. Найчастіше краще звʼязати магазин із системою виставлення рахунків чи бухгалтерією із сертифікованою інтеграцією KSeF, яка сама формує коректний XML, а магазин лише передає дані замовлення. Це знижує ризик, що зміна схеми FA(3) з боку Мінфіну зламає фактурування.
